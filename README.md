# 🏛️ 이더리움 스마트 컨트랙트 역사적 해킹 실험실 (Historic Hacks Laboratory)

본 프로젝트는 블록체인 역사상 가장 악명 높았던 3대 스마트 컨트랙트 해킹 사건을 완벽하게 재현하고 분석하기 위해 구축된 **로컬 전용 이더리움 보안 실습 환경**입니다.

이 저장소에 포함된 자동화된 시뮬레이션 스크립트를 실행함으로써, 실제 해킹이 작동했던 정확한 메커니즘과 스마트 컨트랙트의 상태(State)가 조작되는 과정, 그리고 현대의 표준 방어 기법들이 이를 어떻게 성공적으로 차단하는지 직접 관찰하고 증명할 수 있습니다.

> **⚠️ 로컬 전용 실행 경고 (STRICT LOCAL ISOLATION WARNING):** 본 실험실의 모든 취약한 컨트랙트 코드는 역사적인 보안 결함을 재현하기 위해 의도적으로 작성되었습니다. 이는 **오직 Hardhat 인메모리 네트워크상에서의 로컬 교육 및 시뮬레이션 목적**으로만 사용되어야 합니다. **절대 실제 운영 중인 테스트넷이나 메인넷에 배포하지 마십시오.**

## 🏗️ 프로젝트 구성 및 동작 원리

본 프로젝트는 크게 3개의 해킹 시뮬레이션 모듈로 구성되어 있습니다. 각 모듈은 **취약한 컨트랙트 구현체**, 해킹 과정을 시연하는 **공격 스크립트**, 그리고 보안 대책을 적용한 **수정된 컨트랙트 구현체**를 포함합니다.

모든 시뮬레이션은 Hardhat 로컬 노드 환경에서 `ethers.js`를 통해 자동으로 실행되며, 공격 성공 및 방어 증명 결과는 `logs/` 디렉터리에 상세 로그로 기록됩니다.

### 1. The DAO 해킹 (2016): 재진입성 공격 (Reentrancy)
- **취약점 (`SimpleDAO.sol`):** 사용자의 내부 잔액 상태를 차감하기 **전에** 외부 호출(`call.value`)을 통해 ETH를 먼저 전송합니다.
- **공격 흐름 (`01_dao_attack.js`):** 공격자 컨트랙트가 시드머니 1 ETH를 예치한 뒤 출금을 요청합니다. 자금을 수신할 때 트리거되는 공격자의 `receive()` 폴백(Fallback) 함수 내부에서, DAO 컨트랙트가 잔액을 업데이트하기 전에 `withdraw()` 함수를 재귀적으로 다시 호출합니다. 이 루프는 DAO의 잔액이 완벽하게 0 ETH로 고갈될 때까지 반복됩니다.
- **방어 기법 (`02_dao_fixes.js`):**
  - **CEI 패턴 (Checks-Effects-Interactions):** 자금을 외부로 송금하기 전에 잔액 상태를 먼저 업데이트합니다.
  - **Reentrancy Guard:** 상태 잠금 변수(Mutex lock)를 도입하여 함수가 실행 중일 때 재진입하는 것을 원천 차단합니다.
  - **Pull-over-Push 패턴:** 사용자가 출금을 요청하면 인출 가능한 상태 변수만 기록해 두고, 별도의 안전한 `claimPayment()` 함수를 통해 사용자가 직접 자금을 수령해 가도록 설계합니다.

### 2. 패리티 지갑 해킹 #1 (2017): 비인가 초기화 (Unauthorized Initialization)
- **취약점 (`WalletVulnerable.sol` & `WalletLibraryVulnerable.sol`):** 프록시(Proxy) 지갑은 `delegatecall`을 사용하여 공유 라이브러리의 로직을 빌려 실행합니다. 라이브러리의 `initWallet()` 함수에 접근 제어가 없어 누구나 호출할 수 있었으며, `delegatecall`은 호출자(프록시)의 스토리지 컨텍스트에서 실행되므로 공격자가 라이브러리의 `initWallet()`을 호출하는 순간 **프록시 지갑 스토리지의 0번 슬롯(`owner`)**이 덮어씌워지는 결함이 발생합니다.
- **공격 흐름 (`03_parity1_attack.js`):** 공격자가 아직 초기화되지 않은 프록시 지갑들을 찾아내어 `initWallet()`을 호출하고, 지갑의 소유자(`owner`)를 자신의 주소로 변경한 뒤 내부 자금을 전액 탈취합니다. (스토리지 충돌에 대한 시각적 원리는 `diagrams/delegatecall_storage_collision.md` 참조)
- **방어 기법:** `initialized` 상태 플래그를 도입하여 초기화 로직이 두 번 이상 실행되는 것을 엄격하게 차단합니다.

### 3. 패리티 지갑 해킹 #2 (2017): 라이브러리 자폭 및 자금 동결 (Library Self-Destruct)
- **취약점 (`SharedWalletLibraryVulnerable.sol`):** 1차 해킹 이후 패리티 팀은 새로운 라이브러리를 배포했으나, 라이브러리 자체를 초기화하지 않은 채 방치했습니다. 공격자가 공유 라이브러리 컨트랙트에 직접 `initWallet()`을 호출하여 라이브러리 자체의 소유자가 된 후, 내부의 `selfdestruct` 연산자를 트리거하는 `killLibrary()`를 실행해 버렸습니다.
- **공격 흐름 (`04_parity2_freeze.js`):** 공격자가 공유 라이브러리의 소유권을 획득하고 파괴합니다. 라이브러리의 바이트코드가 `0 bytes`로 소멸함에 따라, 이 라이브러리에 `delegatecall`을 의존하던 모든 프록시 지갑들은 로직을 상실하고 작동 불능 상태에 빠집니다.
- **결과 (탈취가 아닌 영구 동결):** 시뮬레이션 로그를 통해 프록시 지갑 내부에 5 ETH가 그대로 남아있음을 증명합니다. 하지만 실행할 로직 코드가 사라졌기 때문에 합법적인 소유자가 출금이나 트랜잭션을 시도해도 기계적으로 실패(Revert)하며 자금이 영구적으로 동결됩니다.
- **방어 기법:** 라이브러리의 생성자(Constructor)에서 자체 스토리지를 영구 잠금 처리(`owner = address(this)`)하고, 매우 위험한 `selfdestruct` 코드를 베이스에서 완전히 제거합니다.

## 🚀 실행 및 결과 검증

### 환경 설정
시스템에 Node.js가 설치되어 있는지 확인한 후, 아래 명령어를 통해 의존성 패키지를 설치합니다.
```bash
npm install
```

### 시뮬레이션 실행
테스트 스위트를 통해 모든 시뮬레이션을 컴파일하고 순차적으로 실행할 수 있습니다.
```bash
npm test
```

또는 개별 해킹 시나리오만 선택적으로 실행할 수도 있습니다.
```bash
npm run compile
npm run simulate:dao
npm run simulate:dao-fixes
npm run simulate:parity1
npm run simulate:parity2
```

### 실행 결과 분석
실행이 완료되면 `logs/` 디렉터리에 생성된 로그 파일에서 각 시나리오의 결과를 다음과 같이 정확하게 확인할 수 있습니다:

- **`dao_attack.log`**: DAO의 잔액이 `0.0 ETH`로 고갈되고, 공격자 컨트랙트가 정확히 `11.0 ETH`를 소유하게 되었음을 증명합니다.
- **`dao_fixes.log`**: 3가지 방어 기법이 모두 성공하여 공격자의 자금 탈취 시도를 성공적으로 차단했음을 보여줍니다.
- **`parity1_attack.log`**: 비인가된 지갑 2개와 3개가 성공적으로 탈취당했으며, 고정된(Fixed) 지갑은 비인가된 초기화 및 실행 시도가 차단됨을 검증합니다.
- **`parity2_freeze.log`**: 라이브러리 바이트코드가 `0 bytes`로 소멸하여 영구 동결되었음을 증명하며, 소유자 트랜잭션이 기계적으로 실패(Revert)함을 확인합니다.

실행 결과 스크린샷은 `screenshots/` 폴더에 있습니다.
